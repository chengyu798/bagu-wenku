## 导读

读完这篇，你知道 Reflection 的生成—评审—修改循环，什么信号能让反思真正有效，以及什么时候不该用。前置知识：Agent Loop。

## 基础概念

- **生成器（generator）**：产出候选答案、代码或计划。
- **评审器（critic）**：用规则、测试或另一个模型评估候选结果。
- **反馈（feedback）**：具体的失败原因和修改建议。
- **Self-Refine**：在同一任务内反复修改。
- **Reflexion**：把失败反思写入记忆，供下一次尝试使用。
- **外部信号**：测试、编译器、检索证据等客观判据。

## 核心结论

Reflection 让 Agent 先生成结果，再由自己或独立的评审器（critic）评估，把具体问题和修改建议反馈给生成器，进入下一轮修改。它把「一次性输出」变成「带反馈的迭代」，但前提是评审信号足够可靠。

## 原理与机制

**基本循环：**

1. **Generate**：生成候选答案、代码或计划。
2. **Critique**：用规则、测试、检索证据或另一个模型评审。
3. **Refine**：根据反馈修改，再次评审。
4. **Stop**：通过、达到最大轮数，或收益不再增加。

**几种常见形式：**

- **Self-Refine**：同一个模型先写再改，反馈和修改都在同一轮任务内完成。
- **Reflexion**：把失败原因写成「语言化反思」存入记忆，下一次尝试时带上，避免重复犯错。
- **Evaluator-Optimizer**：生成器和评审器分离，评审器可以是另一个模型、测试套件或人类。
- **工具增强反思**：用编译器、单元测试、linter、检索结果作为客观信号，而不是让模型凭空自评。

**什么时候有效：** 任务有可验证的反馈（代码能否运行、答案能否被证据支持、格式是否满足 schema），或者有明确的评分标准。

**什么时候无效：** 没有外部信号、模型对自己的错误缺乏识别能力、任务本身主观。此时反思容易变成自我强化，越改越自信，但不一定越对。

**成本：** 通常增加 2–3 倍模型调用和延迟，需要设置轮数上限和收益判断。

## 具体案例

让 Agent 写一个登录接口：

1. 生成第一版代码。
2. 运行单元测试，空密码和重复用户名两个用例失败。
3. 把失败断言和堆栈作为反馈，要求只修改相关函数。
4. 再跑测试，全部通过后输出。

这里的评审信号是测试，不是模型自评。如果没有测试，只是让模型「再检查一遍」，它往往只会改注释或换措辞，真正的边界 bug 仍然存在。

## 追问链

1. **Reflexion 和 Self-Refine 的区别？** Reflexion 把失败反思写进长期记忆，供下一次尝试使用；Self-Refine 是在同一次任务里反复修改。
2. **为什么模型自评经常不可靠？** 它倾向于认可自己的输出，且看不到自己不知道的信息；引入测试、工具或独立评审器能缓解。
3. **怎么判断反思有没有用？** 和单次生成的基线做 A/B，比较任务成功率、修改幅度和成本，而不是只看某一轮看起来更好。
4. **反思循环怎么停？** 通过标准、最大轮数、连续两轮无实质变化或收益递减，三者满足其一即可。

## 常见误区

- 把「让模型再检查一遍」当成 Reflection；没有具体反馈信号的检查，通常只是换个说法重复原答案。
- 反思不是越多轮越好，后期容易过拟合评审器的偏好，甚至引入新错误。

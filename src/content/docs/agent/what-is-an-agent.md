## 导读

这是整个 Agent 分类的起点。读完这篇，你应该能分清 Chatbot、Workflow 和 Agent 三个概念，知道 Agent 的最小组成，也能判断一个任务到底该不该做成 Agent。前置知识只有一条：知道大语言模型（LLM）是「给定上下文、预测下一个 token」的模型。

## 基础概念

- **LLM（大语言模型）**：根据输入上下文逐 token 生成文本的模型。它本身只会输出文本，不会读文件、发请求或记住上一轮之外的事情。
- **Chatbot（聊天机器人）**：以对话为交互形式，模型根据历史消息直接生成回复。它可以多轮对话，但不会主动调用外部工具，也不会自己决定去查资料或执行动作。
- **Workflow（工作流）**：由开发者预先写好步骤、分支和调用顺序，LLM 只作为其中某些节点的处理函数。控制流在代码里，不在模型手里。
- **Agent（智能体）**：给定一个目标后，由模型自己决定下一步做什么、是否调用工具、调用哪个工具、什么时候停止。控制流的一部分交给了模型。
- **自主性（autonomy）**：模型对「下一步做什么」的决定程度。完全写死是 Workflow，完全由模型决定是高度自主的 Agent，中间还有有限分支、动态选择工具等形态。
- **工具（tool）**：Agent 可以调用的外部能力，例如搜索、读文件、执行代码、调用 API。
- **循环（loop）**：Agent 反复执行「观察 → 决策 → 行动 → 观察」的过程，直到完成或触发停止条件。
- **Harness（运行时）**：模型之外、负责执行工具、管理上下文、控制权限和记录追踪的那层基础设施。

## 核心结论

Agent 是以目标为输入、能自主决定下一步并调用工具、直到完成或停止的执行体。最小组成可以写成：**Agent = 模型 + 工具 + 循环 + 状态**。只调用一次模型输出文本的是 Chatbot；步骤完全写死的是 Workflow；模型掌握控制流、能根据观察调整行动的，才是 Agent。

## 原理与机制

**三者的控制流归属不同：**

| 形态 | 谁决定下一步 | 能否调用工具 | 灵活性与成本 |
| --- | --- | --- | --- |
| Chatbot | 无控制流，一次生成 | 一般不能 | 最低 |
| Workflow | 开发者写死的代码 | 可以在固定节点调用 | 可预测、易测试 |
| Agent | 模型根据上下文动态决定 | 可以自主选择 | 最高，但不确定、更贵 |

**Agent 的最小闭环：**

1. 接收目标与约束，组装上下文。
2. 模型判断当前状态，决定调用工具还是直接回答。
3. Harness 执行工具，把结果回填。
4. 重复，直到信息足够、达到预算或需要人工介入。

**自主性是一条光谱，不是二选一。** 从「固定 pipeline」到「有限分支」到「模型动态选工具」再到「开放式多步规划」，自主性越高，能处理的任务越开放，但可预测性、调试难度和成本也越差。

**什么时候不该用 Agent：**

- 步骤可以提前写清楚、分支有限：用 Workflow，稳定且便宜。
- 任务只需要一次问答：用普通 LLM 调用。
- 高风险、不可逆操作：Agent 可以做，但必须加人工确认和权限边界。
- 评测标准还不清楚：先把任务拆成可验证的 Workflow，再逐步放开自主性。

## 具体案例

**客服退款：**

- Chatbot：用户问「我的订单到哪了」，模型直接回复「请联系客服」，无法查真实订单。
- Workflow：系统先识别意图，命中「退款」后固定执行「查订单 → 校验规则 → 发起退款」，步骤稳定但只能处理预设情况。
- Agent：模型可以先查订单，发现已发货，再查物流政策，判断是否需要人工审核，最后决定发起退款或转人工。它可以处理「已发货但未签收」「部分退款」「优惠券叠加」等没有预先写死的情况。

**代码修复：**

Claude Code 接到「修复登录接口的空指针」后，自己决定读哪些文件、跑哪些测试、改哪一行；如果测试失败，它会看报错继续改。这里控制流由模型掌握，外层 Harness 负责执行和权限，这就是 Agent。

## 常见误区

- **「用了 LLM 就是 Agent」**：不是。一次模型调用、固定 pipeline 都不是 Agent。
- **「工具越多越 Agent」**：工具只是能力，关键看谁决定下一步。
- **「自主性越高越好」**：自主性带来不确定性和成本；能写死的流程尽量写死。
- **「多 Agent 比单 Agent 高级」**：多数任务单 Agent 就够，多 Agent 是特定场景的权衡。

## 追问链

1. **Agent 和 Workflow 的边界在哪里？** 看控制流归属：步骤和分支由代码决定是 Workflow，由模型根据观察动态决定是 Agent。实际系统常常是混合的。
2. **为什么 Agent 需要循环？** 一次调用无法根据工具结果调整行动；循环让模型能「做一步、看结果、再决定」。
3. **怎么判断一个任务该不该用 Agent？** 步骤能否预先写清、失败代价、评测难度、延迟和成本；能 Workflow 就先 Workflow。
4. **Agent 的主要成本是什么？** 多轮模型调用、工具执行、上下文膨胀、评测和调试成本，以及不确定性带来的兜底成本。
5. **什么是 Human-in-the-loop？** 在高风险或不确定的节点暂停，让人确认或补充信息，再继续执行。

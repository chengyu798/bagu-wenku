## 导读

读完这篇，你知道 Agent 应该记什么、什么时候写、怎么取、什么时候忘，以及记忆和 RAG 的区别。前置知识：上下文工程。

## 基础概念

- **工作记忆**：当前任务的状态、计划和中间结果。
- **情景记忆**：过去发生过的交互和事件。
- **语义记忆**：稳定的事实、偏好和知识。
- **程序性记忆**：一类任务怎么做，例如 Skill。
- **巩固（consolidation）**：摘要、抽取、去重、合并冲突版本。
- **检索**：按相关性、新近性和重要性把记忆取回上下文。
- **遗忘**：TTL、低价值清理、冲突更新和用户主动删除。

## 核心结论

记忆工程是设计 Agent 的「上下文之外」的信息系统：把哪些经历、事实和偏好写进长期存储，什么时候巩固和去重，如何在需要时检索回上下文，以及何时遗忘。它解决的是上下文窗口装不下、但任务又需要连续性的问题。

## 原理与机制

**四类记忆：**

| 类型 | 内容 | 例子 |
| --- | --- | --- |
| 工作记忆 | 当前任务的状态和中间结果 | 草稿本、计划、工具结果 |
| 情景记忆 | 过去发生过的交互和事件 | 上次用户说过偏好 Python |
| 语义记忆 | 稳定的事实和知识 | 公司内部术语、项目结构 |
| 程序性记忆 | 怎么做一类任务 | Skill、操作手册、失败教训 |

**四个核心操作：**

1. **写入**：判断什么值得记。通常看重要性、复用概率、置信度和隐私约束。
2. **巩固**：把原始对话摘要成事实，抽取结构化字段，去重、合并冲突版本。
3. **检索**：按相关性、新近性和重要性排序，必要时做混合检索（向量 + 关键词 + 结构化过滤）。
4. **遗忘**：设置 TTL、清理低价值记忆、处理过期或矛盾信息，并允许用户删除。

**常见存储与架构：**

- 向量数据库 + 元数据过滤，适合非结构化片段。
- 知识图谱，适合实体关系和可解释查询。
- 文件式记忆（`CLAUDE.md`、笔记目录、结构化 profile），透明、可版本化，适合个人 Agent。
- 分层记忆：热上下文 / 温摘要 / 冷存储，按需在层之间移动，类似 MemGPT 的思路。

**主要风险：**

- 记忆投毒：恶意内容被写入长期记忆，后续持续影响行为。
- 过期与冲突：旧偏好和新事实同时存在，检索到错误版本。
- 检索噪声：记忆越多，召回的相关性越差。
- 隐私：用户不希望某些信息被长期保存。

## 具体案例

用户第一次说：「我不喜欢过度抽象，优先可读性。」

1. Agent 把这条偏好写入语义记忆，记录来源、置信度和时间。
2. 两周后的新会话里，用户要求重构，Agent 检索到该偏好，默认给出更直白的实现。
3. 用户改口：「这次可以抽象。」Agent 更新记忆，降低旧偏好的权重，而不是直接删掉。

如果没有记忆，每次新会话都要重新说明偏好；如果只存不改，旧偏好会在不合适的时候继续影响决策。

## 追问链

1. **记忆和 RAG 的区别？** RAG 主要检索外部知识库；记忆存储的是 Agent 自身的交互经历、用户偏好和任务结论。
2. **什么时候应该写入记忆？** 重要且可复用的事件、稳定的用户偏好、已验证的任务结论；写入前做去重、置信度判断和隐私检查。
3. **怎么处理新旧记忆冲突？** 保留时间戳和来源，优先新证据；对关键事实做显式合并，而不是让两条矛盾记录同时存在。
4. **怎么评测记忆系统？** 看检索命中率、任务成功率、重复犯错率、上下文 token 成本和用户纠正次数。

## 常见误区

- 把所有对话原文都存进向量库，只会得到噪声更大、成本更高的「伪记忆」。
- 记忆不是越久越好；没有遗忘机制的系统最终会被过期信息和冲突版本拖垮。
